<objective>
Close the final embedded interaction gap by stopping normal mouse-capture release from masquerading as host deactivation.

Purpose: The final manual re-check showed that embedded Delete/C/Tab/Ctrl+Z still failed, gizmo drags snapped back on release, and camera inertia stopped immediately. That symptom bundle means the embedded child was treating normal WM_CAPTURECHANGED/WM_CANCELMODE on mouse release as a runtime cancel, which cleared keyboard ownership and canceled active interactions even though the host never actually regained focus.
Output: Embedded mdCAD keeps keyboard ownership and interaction completion across a normal mouse release, and the child window explicitly claims dialog keys such as Tab from the Win32 host path.
</objective>
