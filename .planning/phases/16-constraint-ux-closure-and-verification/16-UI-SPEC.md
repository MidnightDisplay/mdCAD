## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Frame vertical padding baseline (`FramePadding.y`) |
| sm | 8px | Inline gaps (`igSameLine(..., 8)`), compact control spacing |
| md | 16px | Dimension popup anchor offset from glyph (`+16px`) |
| lg | 24px | Section breathing room in inspector groups |
| xl | 32px | Large panel grouping separation |
| 2xl | 48px | Major section breaks in workspace windows |
| 3xl | 64px | Reserved for full-window spacing only |

Exceptions:  
- 12px is allowed for window/frame padding where existing theme already uses it (`WindowPadding 12`, `Scrollbar/Grab 12`).  
- 18px is allowed for glyph stack spacing (`constraint_glyphs.h`) to avoid overlap in shared-participant stacks.

**Source:** `src/ui/ui_theme.h`, `src/constraints/constraint_glyphs.h`

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#252526` | Main panel/window backgrounds (Visual Studio dark default) |
| Secondary (30%) | `#333337` | Frames, rows, non-active controls, secondary surfaces |
| Accent (10%) | `#0077C8` (active) / `#1D97EC` (hover) | Selection affordances, active tabs/headers, focus/hover emphasis |
| Destructive | `#E78284` | Delete constraint buttons and destructive confirmations only |

Accent reserved for:  
1. Active constraint row emphasis and selected-participant highlight cues  
2. Constraint menu actionable focus state  
3. Dimensional edit “active/focus” affordances  
4. Keyboard focus/navigation markers  

Do **not** use accent for neutral text, static labels, or passive row backgrounds.

## Phase 16 Interaction Contract (Prescriptive)

### 1) Constraint glyph click and participant highlight semantics
- Single-click on a constraint glyph **must**:
  1. set `selected_constraint_entity` to the clicked constraint, and
  2. clear current selection buffer, then add **all alive participants** from that constraint.
- Glyph-click selection behavior must match ConstraintManager row click behavior exactly (same participant set, same immediate frame highlight).
- Constraint entity-only selection (without participant highlight) is not allowed for this phase.
- Hovering a glyph must continue to use constant-screen-size glyph affordance and hover color change.

### 2) Dimensional popup behavior
- Double-click on a dimensional constraint glyph (`LENGTH`, `ANGLE`) opens the dimension popup.
- Popup anchor order:
  1. glyph screen anchor + 16px offset if available,
  2. fallback to last constraint menu anchor.
- Accept paths:
  - `Accept` button and `Enter/KeypadEnter` both commit via `scene_constraint_set_dimensional_value(...)`.
- Dismissal paths:
  - `Cancel`, `Escape`, or outside click close without committing new value.
- Popup must close if the target constraint is deleted or no longer dimensional.

### 3) Constraint manager / viewport parity
- Manager and viewport must mirror dimensional value and driven-state edits through the same scene helper path.
- `Driven` tooltip text remains: “Driven constraints remain visible/readable but do not drive solve equations.”
- Any value/driven update in one entrypoint must be immediately visible in the other entrypoint without reopening windows.

### 4) Keybinding wording consistency (roadmap vs implementation)
- Canonical Phase 16 contract:  
  - `C` opens context-aware constraint menu.  
  - `Tab` toggles gizmo edit mode (Transform ↔ Geometry).
- Verification/validation artifacts must explicitly record this mapping and treat older “Tab-triggered constraint menu” wording as legacy text to be corrected in docs, not in runtime behavior.

**Source:** `src/app.c` keyboard handling + menu/popup flow, `src/ui/ui_entity_inspector.h`, `16-RESEARCH.md`, `ROADMAP.md`/`REQUIREMENTS.md` mismatch note.
