- Added `samples/avalonia-mdcad-control/tools/MdCad.WindowsRuntimeRefresh/` as a repo-local net10 console helper with a thin `Program.cs`, normalized CLI options, and a runtime-refresh orchestrator.

## Decisions Made

- Solved the helper-under-control-tree compile leak by excluding `tools\**\*.cs` from the main control project instead of moving the helper elsewhere.
- Kept the helper API testable via plan creation and injected process execution rather than baking process start directly into top-level code.
- Treated missing `build-vulkan\CMakeCache.txt` as the explicit fail-fast path instead of broadening scope into first-run native build configuration.

## Deviations from Plan

- `MdCad.Avalonia.Control.csproj` needed one tightly coupled compile-glob exclusion in Wave 1 so the new helper’s top-level statements would not be compiled into the control assembly. This was required by the chosen helper location and does not change runtime behavior.

## Issues Encountered

- The new helper initially caused `MdCad.Avalonia.Control` to compile `tools\MdCad.WindowsRuntimeRefresh\Program.cs` via implicit SDK globs, which produced `CS8805`. Excluding `tools\**\*.cs` from the control project resolved it cleanly.
- The helper tests briefly missed `using System.Diagnostics;` for `ProcessStartInfo`; adding the import closed the compile gap immediately.
